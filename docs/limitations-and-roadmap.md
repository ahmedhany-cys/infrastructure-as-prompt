# Known limitations and roadmap

## Limitations (honest list)

**Not tested / not performed**
- No real AWS deployment has been performed. Real-mode apply and live verification are implemented but only unit-tested with fake clients.
- The Anthropic AI provider has not been called against the live API in this environment (no API key was available). Its parsing, validation and fallback are tested with a fake client; the installed SDK's `messages.parse(output_format=…, output_config=…)` signature was checked.
- PostgreSQL: the Alembic migration was generated and applied on SQLite; the app has not been run against a PostgreSQL server.
- The Playwright journey was run with Google Chrome on macOS only.

**Scope**
- AWS only; one architecture pattern (load-balanced web application with optional PostgreSQL).
- Importing or modifying existing infrastructure is not supported; the interview offers a separate environment instead.
- Drift detection is not implemented. Re-validation in real mode refreshes state, so the plan shows differences between real resources and configuration, but there is no scheduled drift check.
- No multi-user accounts: isolation is per anonymous browser session. Not suitable for shared hosting without adding authentication.
- Local Terraform state only.

**Analysis**
- The policy engine resolves references from the plan's configuration section; references passed through `locals` or child modules are not followed (modules are rejected by the safety gate).
- `POL-SEC-002` (credentials in user data/tags) and the execution-safety gate are pattern-based pre-filters. The gate is deliberately conservative (it also rejects forbidden words in comments).
- Checkov and Trivy are advisory; several of their findings (customer-managed KMS keys, Performance Insights, SNS for CloudTrail) are reasonable hardening for regulated workloads but are not generated by default.
- Cost estimates use a static price table (with regional multipliers) rather than the AWS Price List API.
- When several Terraform processes start concurrently on a loaded machine, loading the AWS provider plugin can time out; the pipeline reports this as a failed `validate` step (observed once while two test suites ran in parallel). Re-running succeeds.

**Interview tailoring**
- Business hours for the off-hours schedule are fixed at 07:00–19:00 on weekdays in the region's time zone (editable as the `business_hours_timezone` variable, not asked in the interview).
- Industry and user geography only change recommendations; they never add or remove a control on their own. The industry → compliance mapping is a starting point, not legal advice.
- The supported regions are four (us-east-1, us-west-2, eu-west-1, eu-central-1); users in the Middle East, Africa or Asia-Pacific are offered the closest of these. A CDN is not generated.
- Public IPv4 charges for Lean servers that are switched off overnight are slightly overestimated.

**Generated infrastructure**
- A placeholder application is installed on instances; deploying your own application is out of scope.
- HTTPS requires an ACM certificate you supply; simulation uses a placeholder ARN.
- The ALB access-log bucket policy includes regional ELB account principals for six regions; other regions are rejected by variable validation.

## Roadmap

1. Authentication (OIDC/SSO), organisations and role-based approval (four-eyes for real deployments).
2. Live pricing via the AWS Price List Query API with caching.
3. S3 backend with locking and encryption; per-project state isolation in shared deployments.
4. Drift detection job (`plan -refresh-only`) with a drift report against requirements.
5. Import of existing resources with generated `import` blocks and a review step.
6. More patterns: containers on ECS Fargate, static sites (S3 + CloudFront), serverless APIs.
7. OPA/Rego export of the policy set; OSCAL-style evidence output.
8. Customer-managed KMS keys and stricter profiles for HIPAA/PCI.
9. Tighter deployment-role template generated from the plan's resource types.
10. Azure and GCP providers behind the existing provider-agnostic interfaces.
