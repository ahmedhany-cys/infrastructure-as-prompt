## What this creates

- **VPC 10.20.0.0/16** — Private network with separate tiers per availability zone.
- **Public subnets (2 AZs)** — Only components that must face the internet live here.
- **Private app subnets (2 AZs)** — Servers are not directly reachable from the internet.
- **NAT gateway ×1** — A single NAT keeps cost down; if its AZ fails, outbound traffic from servers stops.
- **Isolated data subnets (2 AZs)** — The database has no path to or from the internet.
- **Application Load Balancer** — Single public entry point; terminates TLS and spreads load across zones.
- **App servers (auto scaling)** — Replaced automatically when unhealthy; scales on CPU.
- **Instance role** — Temporary credentials with only the permissions the servers need.
- **SSM Session Manager** — Administrative access without exposing ports to the internet.
- **RDS PostgreSQL 16** — Managed PostgreSQL with automated backups and patching.
- **Secrets Manager** — Credentials are generated and rotated by AWS, never stored in Terraform.
- **Uploads bucket (S3)** — User files live outside the servers so they survive replacement and scaling.
- **Alerts (CloudWatch → email)** — Your team hears about problems before customers do.
- **Log bucket (S3)** — Private, tamper-resistant store for access, flow and audit logs.
- **CloudTrail** — Records every AWS API call for auditing.
- **VPC flow logs** — Network-level record of accepted and rejected connections.

## Prerequisites

- Terraform >= 1.6 (tested with the version recorded in the evidence report)
- AWS credentials from a profile, SSO session or assumed role with permission to
  create the resources above. Do not use root or long-lived administrator keys.
- An **issued ACM certificate** in us-east-1 for your domain.

## State

State is stored locally (`terraform.tfstate`). Local state is not suitable for
teams or production: it is not locked, not backed up, and contains sensitive
values. For shared use, configure an S3 backend with locking and restrict
access to the state bucket.

## Teardown

```bash
terraform plan -destroy -out=destroy.tfplan
terraform apply destroy.tfplan
```
Deletion protection is enabled on the database and load balancer. Disable it
deliberately (a separate reviewed change) before destroying. A final database
snapshot is retained and continues to incur storage charges until deleted.
The log bucket is not force-destroyed: empty it first if you really intend to
delete the audit logs. Check the AWS Billing console afterwards; some charges
(snapshots, logs, CloudWatch data) can outlive the stack.
